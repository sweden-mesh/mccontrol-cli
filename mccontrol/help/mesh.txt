Repair a node over the mesh

When a repeater's Wi-Fi or MQTT fails -- a new Wi-Fi password, a moved
access point, a renamed broker -- it drops off the control plane, but its
radio is still on the mesh. From lou-19 a node with the plane (rc) also
takes your signed commands as a LoRa request, sent through your own
companion radio. Same key, same signature, same counter: a command
delivered both ways runs once. The answer comes back over the air.

Switch on while it works
  The node's mesh road is the setting mqtt.cmd.mesh: auto (the default)
  opens it once MQTT has been down 15 minutes; on keeps it open; off
  shuts it. Check it now, while MQTT works: send "get mqtt.cmd.mesh".
  If a node says off, set it on its console. A device group (see
  [[cli]]) reads it from every node in one go.
  Make sure each device has its whole public key (discovery stores it):
  the request is encrypted to that key.
  Set your companion once:
    mccontrol config --companion tcp:10.0.0.5:5000
    (or serial:/dev/ttyACM0, or ble:AA:BB:CC:DD:EE:FF)
  A tcp: companion runs the Wi-Fi companion firmware, which listens on
  port 5000 and serves one client: each mesh command drops whatever held
  it (the phone app). To share it, put a mux in front and give mccontrol
  the mux's port (tcp:<host>:5001). The web app reaches it through
  mccontrol-bridge.

The recipe
  1. Connect your companion, in reach of the node or of the mesh.
  2. Send the repair over the mesh:
       mccontrol send loutest set wifi.ssid HomeNet --via mesh
       mccontrol send loutest set wifi.pwd s3cret --via mesh
     or point the command slot at the broker:
       mccontrol send loutest set mqtt.cmd on mqtt-meshcore.louie.se --via mesh
  3. Reboot to apply it:  mccontrol send loutest reboot --via mesh
     A reboot answers nothing; the node restarts first.
  4. Confirm on MQTT, a few minutes later:  mccontrol send loutest ver

What the mesh road admits
  Everything the plane admits over MQTT, and only here the repair:
  set wifi.ssid, set wifi.pwd (each with a value), set mqtt.cmd on and
  set mqtt.cmd on <host>. The broker slots' settings (set mqttN.*) travel
  too, so a broken Observer feed can be repaired over the mesh as well.
  Everything else denied stays denied. A command
  is at most 57 bytes to a node on lou-20 or later (sealed) and 59 to
  one on lou-19, checked before it is signed. One node at a time,
  never a region; the node answers at most one command a minute and ten
  an hour this way, since each costs airtime on a shared network.

Answers and silence
  mesh-closed: the node's MQTT works, so it takes commands over MQTT;
  send it there. Silence is not a refusal: a node on older firmware,
  a bad signature, a replay or the minute budget all say nothing.
  The first request to a node with no known path floods once; its
  answer teaches your companion a path, and the next one goes direct.

--via auto
  Takes the mesh for a mesh-only node, for a command only the mesh
  admits, for a node whose status Beacon has not seen for 15 minutes
  (mccontrol config --mesh-after-mins), or when the broker cannot be
  reached; otherwise MQTT. A mesh-closed answer is sent again over MQTT.
  History says which road each command took.

Through a relay
  From lou-20 a node of yours on MQTT can send the request for you, so
  you need no companion. It sends the same mesh request to the other
  node and returns the answer over MQTT:
    mccontrol send cabin ver --via relay:loutest
  The relay sends it direct, with no hops. That is right when the node
  hears the relay itself. For a node further away, give the hops
  (--path A1B2) or flood once: --route flood stays in the relay's
  region, --route flood-wide uses its default scope. An answer teaches
  the path, and the next direct send through that relay uses it.
  One node at a time, and only what the mesh road admits. Here you
  name the relay. The web app's auto may take one that hears the node
  directly, never a flood. A relay sends 10 commands an hour,
  2 of them floods, one at a time, and waits two minutes for the
  answer. "no answer" is not a refusal: the node may have run the
  command. Relaying is on by default. Switch it with
  "set mqtt.relay off" or "set mqtt.relay own"; "get mqtt.relay"
  shows what is left of the hour.

Mesh-only nodes
  A node built without Wi-Fi (an rc image with no -observer in its
  version) takes commands over the mesh alone. Its commands are signed
  for the region named mesh, and it refuses the Wi-Fi and MQTT repair,
  ota check, ota update, mqtt.cmd ping and the broker slots' settings
  (set mqttN.*). The command key is set on its
  console, as on every node.
