Your signing key

Every command is signed with an Ed25519 key kept on this machine
(key.seed in the configuration directory, readable only by you). A
repeater accepts commands signed by exactly one public key, the one
given to it over its serial console:

  set cmd.pubkey <your 64-hex public key>
  set cmd on

Those are the names on lou-20 or later; on lou-19 and older type
"set mqtt.cmd.pubkey" and "set mqtt.cmd on". The second line does
the rest: with no slot configured the node takes its first free MQTT
slot (3-6), points it at the default broker mqtt-meshcore.louie.se with the
built-in "mccontrol" preset, and says "reboot to apply". A board without
PSRAM runs two slots at once; if both are its analyzer uplinks, the node
says so and asks you to turn one off (set mqtt2.preset none) -- it never
does that for you. A region's own command broker takes "set cmd on
<host>" instead; [[ownregion]] has the lines. A board without Wi-Fi
takes the same two lines and answers "mesh only" to "get cmd"; see
[[meshonly]].

The first key without a cable (lou-20)
  A remote admin, logged in to the node over the mesh with its admin
  password, may type "set cmd.pubkey <key>" too, so a board on a mast
  needs no climb. Only the first key: replacing or clearing one stays
  on the USB console. The node refuses while its admin password is the
  default, is shorter than 8 characters, or is the same as the guest
  password, and says which. This tool does not log in as an admin; use
  the MeshCore app's remote management.

Replacing the key
  Each interface shows the two lines above, creates a key when there
  is none, imports an existing seed, and replaces the key -- which
  silences every repeater provisioned with the old one. Where this is
  in your interface is in [[keys]]. Move the nodes first:
  From lou-20, "rekey <new public key>", signed by the key in use, on
  MQTT or the mesh. The new key waits on the node for 60 minutes, or
  until it restarts. It takes over the moment a command arrives that
  the new key signed; if none comes, it is forgotten and nothing has
  changed. So a mistyped or lost key does no harm.
    python -m mccontrol.rekey start     make the next key; sends nothing
    python -m mccontrol.rekey send <node> --via relay:<relay>
                                        nodes behind a relay first
    python -m mccontrol.rekey send --all   then every node on MQTT
    python -m mccontrol.rekey status
    python -m mccontrol.rekey finish    the next key becomes yours
  A node that did not answer keeps the key in use; run send for it
  again within the hour. "abort" forgets the next key while no node has
  taken it. The web app does the same round: Setup, Key, "Replace the
  key on your nodes". A backup file moves the key between the two.
  A node on lou-19 or older, and a key you no longer hold, need the new
  key on the USB console.

The seed is never shown and never leaves the machine inside anything but
a signature. "refused: sig-invalid" from a node means it holds a
different public key than this one.

The same key signs you in to the default broker (see [[broker]]).
Registering it (beside the key in each interface, or "mccontrol
register") publishes your public key to the broker once, signed by the
key itself; from then on the broker checks every command against the
registered keys before it reaches any node, and a login that keeps
sending badly signed commands is locked out for 48 hours after five in a
day. Register once per key and broker, never per device: with a region
on its own broker, registering covers every broker in use.

See [[protocol]] for what the signature covers.
