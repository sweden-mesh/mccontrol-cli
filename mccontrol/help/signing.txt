Your signing key

Every command is signed with an Ed25519 key kept on this machine
(key.seed in the configuration directory, readable only by you). A
repeater accepts commands signed by exactly one public key, the one
given to it over its serial console:

  set cmd.pubkey <your 64-hex public key>
  set cmd on

Those are the names on lou-20 or later; on lou-19 and older type
"set mqtt.cmd.pubkey" and "set mqtt.cmd on". The second line does
the rest: with no slot configured the node takes its first free MQTT
slot (3-6), points it at the default broker mqtt-meshcore.louie.se with the
built-in "mccontrol" preset, and says "reboot to apply". A board without
PSRAM runs two slots at once; if both are its analyzer uplinks, the node
says so and asks you to turn one off (set mqtt2.preset none) -- it never
does that for you. A slot for a region's own command broker is set by
hand (set mqttN.preset custom, server, audience; set cmd.slot N);
[[ownregion]] has the lines.

Each interface shows that command on one line, creates a key when there
is none, imports an existing seed, and replaces the key -- which
silences every repeater provisioned with the old one until each is
re-provisioned. Where this is in your interface is in [[keys]].

The seed is never shown and never leaves the machine inside anything but
a signature. "refused: sig-invalid" from a node means it holds a
different public key than this one.

The same key signs you in to the default broker (see [[broker]]).
Registering it (beside the key in each interface, or "mccontrol
register") publishes your public key to the broker once, signed by the
key itself; from then on the broker checks every command against the
registered keys before it reaches any node, and a login that keeps
sending badly signed commands is locked out for 48 hours after five in a
day. Register once per key and broker, never per device: with a region
on its own broker, registering covers every broker in use.

See [[protocol]] for what the signature covers.
