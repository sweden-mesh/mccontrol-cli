Discovering repeaters

Nodes on lou-20 or later are found from their alive messages: each keeps
a sealed message on the broker that only its owner's key opens. A
discovery reads them all, sends nothing, asks for no region, and lists
the nodes that are yours wherever they are: online, offline, or no longer
yours (given another key). Found nodes are added with no region; they
need none. "mccontrol discover" (no region) does this on the command
line, "--add" keeps what it finds; each interface's discover key does the
same ([[keys]]).

An Observer node with a command key publishes its alive message soon
after it connects, then about every 15 minutes, so a node you have just
set up appears by itself within a few minutes. It carries the node's
version, region home, name, uptime, clock and how the plane is set.
"set alive.interval <5-1440>" changes the minutes between them and
travels over the plane; "get alive.interval" reads it. The broker clears
the message when the node drops off, which is what "offline" means. After
a network drop a node is back after about 3 minutes.

A mesh-only node, one without Wi-Fi, has no MQTT and sends no alive
message. From lou-21 it announces itself over the mesh instead: at start
and then every 23 hours, with its name, version and battery level. An
Observer node of yours that hears the announce keeps it on the broker,
sealed to your key, and the same discovery reads it. The node is listed
as "heard", with the node that heard it, and is added as a node without
Wi-Fi. Its battery is shown with its age: "3.71 V, 9 h ago, heard by
<node>". Nothing is sent and no airtime is used. A lou-20 node without
Wi-Fi does not announce, and nor does one that no Observer node of yours
hears: add it by its public key; see [[meshonly]].
A node without a command key sends none either.

Nodes on lou-19 or older publish no alive message and are found by
region, the only place a region is still asked for: "mccontrol discover
<region>", or the interfaces' "discover a region (lou-19 and older)". It
sends one harmless read ("get autoreply"), signed with your key, to that
region's broadcast topic, and listens for answers. Only a node that
verified your signature publishes a result, so every node in the list is
yours; a node with another key, or none, says nothing. Several regions go
in one run -- "JKG, GOT" -- and "*" asks every region your directory
spans, one signed read per region.

The found nodes are listed with what each answered and "= name" where it
is already in your directory. Any of them, or all, are added to the
directory; a node the fleet gave no name is asked for one, or added
unnamed, to be named later. A node found by its alive gives its own name.

On lou-19 and older, a second read, "get name", fills in names on
firmware that admits it; older firmware refuses it and those nodes stay
unnamed.
