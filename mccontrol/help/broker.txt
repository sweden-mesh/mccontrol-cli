The control broker

Commands and results travel through an MQTT broker, the one each
repeater's cmd.slot points at. Nodes on lou-20 or later all use the
shared broker, with no region. For lou-19 and older the shared broker
serves every region; a region may run its own, and then the configuration names it
for that region ("mccontrol config --region-broker VGR=<host>"). Each
device is reached through its region's broker, and each device shows
which one. The configuration also holds the port, username, password
and how long to wait for answers, the same for every broker. Your key is
registered once per broker. [[ownregion]] has the steps. The broker
test connects with those, subscribes to a test topic, publishes to it
and checks the broker delivers it back; each step is reported and the
first failure named ("Not authorized" is the broker rejecting the
username or password). "mccontrol config" and "mccontrol test" do the
same ("mccontrol test --region VGR" tests a region's own broker); where
they are in your interface is in [[keys]].

This is not the broker the repeaters' statistics go to; those credentials
are not used here.

Signing in. With no username set, the tool signs in to the broker the
way a node does: the username is "v1_" plus your public key and the
password a token signed by your key, renewed each session -- nothing to
hand out, nothing to type. That is how the default broker,
mqtt-meshcore.louie.se, knows who is publishing. A login from the broker's
password file sets its username and password here, and then those are
used.
