Through a relay

From lou-20 a node of yours that is on MQTT can send a command by radio
to a node that is not: a mesh-only node (see [[meshonly]]), or one whose
Wi-Fi or broker has failed (see [[mesh]]). You need no companion radio.
The node that sends is the relay; the node the command is for is the
target.

  mccontrol send cabin ver --via relay:loutest

What can be a relay
  An Observer image with remote control (rc or arrc) on lou-20 or later,
  on MQTT, and in radio reach of the target, directly or over the mesh.
  On lou-20 it must hold the SAME command key as the target: it serves
  the holder of its own command key and nobody else, and a node without
  a command key never relays. A mesh-only node cannot: it has no MQTT.

Someone else's Observer (lou-21)
  From lou-21 any Observer relays for anyone, within half of its
  budget, unless its owner set "relay own" or "relay off". A lou-21
  node with no command key of its own still relays for others. The Observers that caught a node's announce are kept with the
  node (see [[meshonly]]), and any of them can be the relay: name it, or
  let the tool choose.
    mccontrol send cabin ver --via relay:auto
    mccontrol send cabin ver --via relay:7316CA78
  auto takes your own Observer if it caught the node, else the one with
  the fewest hops, then the best signal. A relay that twice in a row
  brought no answer from the node is moved to the end of the list, and
  auto skips it; name it to use it anyway. A stranger's Observer is
  reached with a guest forward, sealed between you and that relay. It
  can refuse with:
    guest-cap     you used the floods it gives one guest today.
    guests-full   its share for guests is used up today.
    target-cap    the node had all the floods from guests it allows.
  Nothing was sent then. Its count starts again at midnight UTC.

What the relay does
  It sends the mesh request the tool built for the target, waits up to
  two minutes, and returns the target's answer over MQTT. It runs
  nothing itself and cannot read the request or the answer: both are
  sealed between the target and you.

The route
  direct      one transmission, no hops: right when the target hears
              the relay itself. The default.
  --path A1B2 direct along the hops you give ("2:A1B2C3D4" for two-byte
              hashes, "--path none" for no hops again).
  --route flood       a flood in the relay's region home.
  --route flood-wide  a flood in the relay's default scope, which is
                      wider.
  An answer teaches the path. The next direct send through that relay
  uses it. A flood costs every repeater that hears it airtime, so flood
  once to learn the way, then send direct.

One command at a time
  A relay holds one command until its answer comes, or two minutes. A
  second one sent meanwhile is answered busy, or dropped unanswered if
  the two arrive together; the first goes through. Send one and wait
  for its answer. One node at a time: never a region, a county
  or a group.

The relay's budget
  Airtime: 5 % of 15 minutes (45 s on the air, about 26 commands), then
  1 % of the next 15 minutes (9 s, about 5), then a burst again.
  Floods: one a minute in a burst, one in five minutes after it, 100 a
  day, and two an hour for floods that leave the relay's region home.
  The budget is fixed. A restart of the relay opens a new burst.
  "get relay" sent to the relay shows what is left:
    > any, forwarded 3, answered 2, refused 1, burst, 39.9 s airtime
    left, floods today 1 of 100, guests: 3 keys, 7 floods today
  "guests" is what other owners sent through it today; a node on
  "own" shows no guests.

What comes back
  The target's answer, with how well the relay heard it. Or one word
  from the relay:
    no answer     sent, nothing came back. Not a refusal: the target
                  may have run the command. See [[mesh]], "No answer".
    rate-limited  the relay's budget is used up. Wait a few minutes.
    busy          another command was waiting on the relay.
    off           relaying is switched off on the relay.
    clock-unset   the relay has no clock yet.
    expired, replay, bad-body, send-failed   nothing was sent.
  With every word but "no answer", nothing went on the air.

Switch relaying
  set relay any    relays for you and, within its caps, for other
                   owners. The default from lou-21.
  set relay own    relays for the holder of its own command key only,
                   lou-20's default. A node updated from lou-20 starts
                   on any; type this once to keep it to yourself.
  set relay off    relays for nobody.
  set relay.guest <0-100>
                   floods a day for each other owner, default 10.
  All travel over the plane, so no visit is needed. "get relay" and
  "get relay.guest" read them. lou-20 knows only own and off.

Who picks the relay
  On the command line you name the relay; --via auto never takes one.
  The web app's Auto may take a relay that hears the target directly,
  when no companion is connected, and never by a flood.

History keeps the relay, the route, how the command was sent and how
well the relay heard the answer (see [[history]]).
